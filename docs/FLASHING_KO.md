# v6 배터리 상태 확인 기능: 이번에는 세 장치 모두 업데이트

이 ZIP은 전체 소스입니다. UF2가 들어 있는 완성 펌웨어가 아닙니다.
실제 ARM 빌드와 기판에서의 센서/무선/OLED 검증은 아직 하지 못했습니다.

## 적용할 파일

GitHub 저장소 같은 위치에 전체 소스를 덮어쓰고 커밋합니다. 바깥 ZIP 폴더가 아니라
`.github`, `config`, `local-modules`, `scripts`, `tests`, `build.yaml` 등이 최상위에 있어야 합니다.
새 `Build MODU-C + Dongle` 빌드가 성공하면 `modu-c-dongle-firmware` 결과물을 받습니다.

| 실제 장치 | 새 빌드 결과물의 파일 |
|---|---|
| 왼쪽 모두 C | `modu_left.uf2` |
| 오른쪽 모두 C | `modu_right.uf2` |
| OLED 동글 | `modu_dongle_oled.uf2` |

이번에는 **동글만 바꾸면 안 됩니다.** 좌우에 전압/측정상태 전송 기능이 추가됐기 때문입니다.
v5 문서에 있던 "동글 하나만 업데이트"는 v5 테마 수정에만 해당합니다.
이미 입력이 되는 현재 연결은 초기화하지 않습니다. **`settings_reset`은 넣지 마세요.**
현재 동작 중인 UF2 세 개는 복구용으로 보관합니다.

좌우는 동글 연결이 살아 있는 동안 기존 부트키를 사용합니다.
- 왼쪽: 기본 레이어에서 `5`만 3초 이상 누른 채 `1`을 누릅니다.
- 오른쪽: 기본 레이어에서 `6`만 3초 이상 누른 채 `0`을 누릅니다.
한쪽씩 새 UF2를 적용하고, 동글은 마지막에 업데이트합니다.
동글에는 기존에 쓰던 물리 부트로더 진입 방법을 사용합니다.
세 파일 적용 후 동글과 좌우 전원을 껐다 켜서 새 GATT 서비스를 다시 찾게 합니다.
이 전원 재시작은 설정 초기화가 아닙니다.

## 화면에서 확인할 것

기존 화면 배치, 고양이, 레이어, Mac 수정키 기호와 테마 설정은 유지합니다.
D(동글) 행은 v5 그대로이며, 이번 신규 기능의 대상은 L/R입니다.
처음에는 `--%`가 보일 수 있습니다. 새 클라이언트는 시작 후 8초부터 읽기를 시작하며,
이후 약 10초 간격으로 좌우를 조회합니다. 정상 잔량은 변경 시점/연결에 따라 갱신됩니다.
이 간격은 펌웨어 설정값이며 실제 첫 표시 시간의 보장이 아닙니다.

| 표시 | 의미 |
|---|---|
| `L 85%` / `R 73%` | 해당 키보드 센서가 성공적으로 측정/환산한 잔량(표의 숫자는 예시) |
| `--%` | 새 측정 정보나 손 구분 정보를 아직 받지 못함. 0%로 대체하지 않음 |
| `ERR` | 센서 준비, 측정, 전압/퍼센트 읽기 중 오류. 실제 잔량은 알 수 없음 |
| `ADC?` ↔ 전압 | 단일 셀 기준 확인이 필요한 측정 전압. 방전 또는 측정회로/설정 이상을 단정하지 않음 |
| `0%` ↔ `3.30V` 등 | 센서가 성공적으로 읽혔지만 기존 환산식 결과가 0. 측정된 전압을 3초마다 교대로 표시 |
| `OLD` | 100초를 초과한 오래된 샘플. 최신 잔량으로 표시하지 않음 |
| `OFF` | 식별된 해당 키보드의 연결이 현재 끊겨 있음 |

새 좌우 펌웨어가 어느 손인지 직접 알려주므로, 새 배터리 정보가 도착하면
키를 눌러 좌우를 가르칠 필요가 없습니다. 연결 순서와 손을 동일하다고 가정하지 않습니다.

**이 업데이트는 센서 전압 자체가 잘못된 문제까지 자동 교정하는 버전이 아닙니다.**
여전히 0이거나 ADC?/ERR라면 그때 보이는 전압/상태가 원인을 좁히는 정보입니다.
배터리 측정 핀, 분압 저항 비율, 퍼센트 환산식은 제작자 원본 그대로입니다.
회로를 확인하지 않고 저항 비율을 임의로 두 배로 하거나 배터리 수치를 만들어 내지 않았습니다.

`fallback/modu_dongle.uf2`는 화면 없는 대체 버전으로 v5의 기본 BAS 경로를 유지합니다.
새 측정상태 표시 기능은 OLED 버전에 들어 있습니다.
