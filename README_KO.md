# MODU-C 동글 검사 오류 + 왼쪽 Tab/단축키열 수정

## 이 ZIP의 범위

이 파일은 전체 펌웨어나 UF2가 아니라, 앞서 전달한 `modu-c-obrey-dongle-complete.zip` 기반 저장소에 적용하는 **부분 수정 패키지**입니다. 동글 보드, 양쪽 트랙볼 배선/드라이버, 빌드 대상, `135 / 680` 부트로더 확장은 바꾸지 않습니다. 현재 키맵을 통째로 교체하지 않습니다.

## 오류를 재현한 원인

기존 `scripts/validate.py`는 `vendor/modu-c-firmware`의 파일을 원본 ZIP의 바이트 해시와만 비교했습니다. 원본 `zmk-pmw3610-driver/Kconfig`는 Windows형 CRLF 줄바꿈입니다. 이를 LF로 바꾸면 코드 내용이 그대로여도 해시가 달라집니다.

원본 저장소를 실제로 Git에 `core.autocrlf=true`로 추가하고, Linux형 체크아웃을 만든 뒤 아래 오류를 재현했습니다.

```
ERROR: Vendored hardware changed: zmk-pmw3610-driver/Kconfig
```

원본에는 CRLF와 LF가 섞인 파일도 있어 Kconfig 하나만 복구하는 방식은 다음 파일에서 다시 막힐 수 있습니다. 수정본은 **업로드된 원본 하드웨어 ZIP으로부터 만든 기준값**으로 CRLF→LF 차이만 허용합니다. 기존 `reference/hardware-sha256.json`은 그대로 두며, 현재 작업 폴더의 변형 파일을 기준으로 해시를 자동 갱신하지 않습니다.

실제 소스 변경, 공백/탭 변경, BOM 추가, 마지막 줄바꿈 제거 등은 여전히 실패합니다. `reference/hardware-normalized-sha256.json`은 안전장치를 제거하는 파일이 아니라 원본 텍스트의 정규화 기준입니다.

GitHub 공식 줄바꿈 안내: https://docs.github.com/en/get-started/git-basics/configuring-git-to-handle-line-endings

실제 사용자의 원격 저장소 파일을 내려받은 것은 아닙니다. 동일 원인을 첨부된 소스로 재현했습니다. 작업 폴더에 줄바꿈 이외의 드라이버 변경이 있으면 이 도구는 수정하지 않고 멈춥니다.

## 왼쪽 키 위치 변경

숫자열의 게임 모드 키는 그대로 둡니다. Base의 문자 영역 왼쪽 바깥열만 다음과 같이 바꿉니다.

| 위치(0부터) | 짧게 누름 | 길게 누름 |
|---|---|---|
| 12: 문자 첫 행 맨 왼쪽 | Tab | 일반 Tab 유지 |
| 24: 홈로우 맨 왼쪽 | 기존 실행 취소 | 기존 전체 선택 |
| 36: 문자 마지막 행 맨 왼쪽 | 기존 복사 | 기존 잘라내기 |
| 48: 왼쪽 보조행 맨 왼쪽 | 기존 붙여넣기 | 기존 동작 그대로 |

정확한 작업은 `12←48`, `24←12`, `36←24`, `48←36`의 네 바인딩 이동입니다. 기존 수정키 코드(예: LG/LC), 다른 문자, 엄지, 게임, 마우스, Nav/Fn, 그리고 사용자가 추가한 콤보는 다시 쓰지 않습니다. Base가 바뀌므로 `&trans`로 Base를 참조하는 위치는 새 Base 동작을 따릅니다. 상위 레이어에 별도 지정한 키는 유지됩니다.

이미 12번이 Tab이면 다시 이동하지 않습니다. 48번이 더 이상 일반 Tab이 아니면 위치를 추측하지 않고 중단합니다. 이 경우 검사기만 적용할 수 있습니다.

## 적용 방법: 권장

1. ZIP을 **기존 저장소 바깥**의 폴더에 풀어 `APPLY_FIX.cmd`를 실행합니다. Python 3가 필요합니다.
2. 경로를 물으면 **현재 동글 저장소의 로컬 폴더 경로**를 붙여 넣습니다. GitHub URL을 넣는 곳이 아닙니다. 선택한 폴더 안에는 `config`, `vendor`, `local-modules`, `build.yaml`이 있어야 합니다.
3. 파일 목록과 키 위치 변경을 확인하고 `Y`를 입력합니다. 저장소 옆의 `저장소명-backup-eol-tab-날짜` 폴더에 변경 전 파일을 백업합니다.
4. 도구가 검사기와 52개 Python 테스트를 실행합니다. 성공하면 화면에 출력되는 **파일별 `git add` 명령**을 사용하고, 커밋/푸시합니다. 자동 커밋/푸시나 플래시는 하지 않습니다.
5. GitHub Actions에서 **새 커밋의 작업**을 확인합니다. 이전 실패 작업의 재실행만으로는 새 수정이 반영되지 않습니다.

명령어로 실행하려면:

```powershell
python .\apply_fix.py --repo "D:\Dev\projects\현재-동글-저장소"
```

검사기만 고치고 키맵은 그대로 두려면:

```powershell
python .\apply_fix.py --repo "D:\Dev\projects\현재-동글-저장소" --keep-keymap
```

기존 에디터 편집 내용을 먼저 로컬에도 반영해 두세요. 수정 도구는 현재 로컬 파일만 읽으며 GitHub의 더 새로운 파일을 자동으로 가져오지는 않습니다.

## 실제 수정 파일

- `scripts/validate.py`: 원본 내용 보존 검사에서 줄바꿈 차이만 허용.
- `reference/hardware-normalized-sha256.json`: 원본 ZIP에서 산출한 LF 기준.
- `tests/test_dongle.py`, `reference/validation-fixture.keymap`: 회귀시험용 고정 예제를 실제 사용자 키맵에서 분리. 에디터에서 일반 키/콤보를 변경했다는 이유만으로 실패하지 않도록 수정.
- `tests/test_line_endings.py`: 줄바꿈, 원본 내용 변경 검출, 네 자리 이동 및 사용자 편집 보존 시험.
- `scripts/move_tab_column.py`: 네 자리만 옮기는 도구. 단독 실행은 기본 미리보기이며 `--apply`일 때 백업 후 기록.
- `.gitattributes`: 기존 내용은 보존하고 우리 줄바꿈 규칙만 추가.
- `config/modu.keymap`: 요청한 Base 네 자리만 변경. 사용자의 스페이스/한영 콤보 등은 건드리지 않음.

`vendor` 파일, `build.yaml`, 워크플로, C 확장, 원본 해시 목록은 이번 패치로 수정하지 않습니다. 펌웨어 빌드 설정을 새로 갈아엎는 패키지가 아닙니다.

## 확인한 범위

- 원본 패키지의 Git 줄바꿈 변환/재체크아웃으로 오류 재현.
- 패치 적용 후 재커밋/새 Linux 체크아웃에서 검사 및 테스트 통과.
- 전체 vendor를 LF 또는 CRLF로 바꾼 두 경우 모두 통과.
- 원본부터 LF/CRLF가 혼재한 드라이버 파일도 처리.
- 실제 드라이버 내용 변경은 거부. 원본 해시 파일을 바꾸는 우회는 없음.
- Base 네 자리만 이동. 반복 실행은 추가 이동하지 않음.
- 사용자 추가 DF/SD 콤보, 콤보 이름 변경, 수정키 변경을 보존한 상태로 검사 통과.
- Python 회귀시험 52개 통과.
- 변경하지 않은 C 확장의 기존 호스트 모의시험(25개×2설정) 재실행 통과.

**실제 ZMK/ARM 펌웨어 컴파일, 동글 무선 통신, OLED, 트랙볼, 좌우 부트로더의 실물 시험을 통과했다는 뜻은 아닙니다.** 이번 확인은 현재 `validate.py` 실패와 요청한 키 위치 이동에 대한 것입니다. 기존 정상 UF2를 보관하고 새 Actions의 실제 빌드가 성공한 후 적용하세요.

시험별 결과와 로그는 `VALIDATION.json`, `reports/`에 있습니다. 테스트 중 생성한 가짜 UF2 입력은 시험용이며 이 ZIP에 설치용으로 제공하지 않습니다.

## 실패·복구

적용 중 로컬 검사가 실패하면 도구는 이번에 바꾼 파일을 백업 상태로 되돌리며, 백업 폴더의 `checks.log`에 실패 로그를 남깁니다. 동시 편집으로 별도 변경된 파일은 임의로 되돌리지 않습니다.

수동 복구는 백업 폴더의 기존 파일을 원래 경로에 돌려놓고, `restore-info.json`의 `new_files_to_remove_when_restoring`에 있는 이번 신규 파일을 정리하는 방식입니다. `.git`과 원격 URL은 수정하지 않습니다.
