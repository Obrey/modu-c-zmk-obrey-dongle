# MODU-C + Corne dongle — v7 연결 유지형 절전 대기

이 ZIP은 **GitHub에 올릴 전체 소스**입니다. 컴파일된 UF2가 아닙니다.
기준: `modu-c-dongle-v6-battery-monitor.zip`. 기존 커스텀 키맵/부트키/트랙볼/맥 아이콘/화면 배치를 유지합니다.

## 설치

이 폴더 **안의 내용**을 GitHub 저장소 최상위에 덮어씁니다. `.github` 포함.
`Build MODU-C + Dongle`의 **새 빌드가 성공한 결과물** `modu-c-dongle-firmware`에서:

| 순서 | 장치 | 적용 파일 |
|---|---|---|
| 1 | 동글 | `modu_dongle_oled.uf2` |
| 2 | 왼쪽 | `modu_left.uf2` |
| 3 | 오른쪽 | `modu_right.uf2` |

**이번에는 세 장치 모두 업데이트. 연결이 이미 되므로 settings_reset은 넣지 않습니다.**
화면 없는 복구용은 `fallback/modu_dongle.uf2`. 현재 동작하는 v6 UF2도 별도로 보관하세요.
새 동글은 이전 v6 키보드의 배터리 데이터도 읽습니다. v6 동글은 새 v7 배터리 확장 데이터를 해석하지 못하므로 동글을 먼저 바꿉니다.

## 동작

30초 무입력 → 연결은 유지하면서 키보드 LED를 끕니다. 키 입력/트랙볼 움직임은 기존 경로로 계속 감지합니다.
사용 중 LED 밝기 설정은 12%에서 6%로 낮추고, 같은 PWM 값을 반복해서 쓰지 않습니다.
배터리 추가 측정은 사용 중 60초, 대기 중 300초 간격. 대기 중 조회 요청마다 ADC를 다시 읽지 않습니다.
동글 조회 간격은 정상 사용 중 30초, 대기 중 60초입니다. 최초 대기/에러는 별도 재시도합니다.
각 숫자는 구현 설정값이며 배터리 수명이나 절전 전류를 측정한 수치가 아닙니다.

배터리 영역은 퍼센트와 전압을 3초씩 교대합니다. `L~3.32V`의 `~`는 **연결 대기 중 마지막 측정값**이라는 뜻입니다.
`OFF`, `ERR`, `--%`, `OLD`는 각각 연결 해제, 센서 실패, 미수신, 오래된 자료로 구별됩니다.
모든 글자는 기존 배터리 영역 폭(7글자)에 맞춥니다. 맥 수정키와 테두리/테마 설정은 바꾸지 않았습니다.

## 3.32 / 3.33V인데 0%인 이유

고정 ZMK의 기존 환산은 **3.45V 이하 = 0%, 4.2V 이상 = 100%**입니다.
따라서 두 수치는 그 계산에 따르면 0%입니다. 20분 충전만으로 충분한 충전이나 정확한 전압 측정을 보장할 수 없습니다.
이번에는 %를 억지로 올리거나 ADC 핀/분압비를 추측하여 바꾸지 않았습니다.
자세한 구분과 판매자에게 확인할 사항: `docs/V7_BATTERY_AND_POWER_KO.md`.

## 왜 깊은 절전은 안 켰나

원본 드라이버는 이 기판의 GPIO 인터럽트 제약 때문에 입력을 폴링하는 경로를 사용합니다.
소스에도 해당 모드가 깊은 절전에 제약이 있음을 설명합니다. 일반적인 `ZMK_SLEEP=y`만 넣으면 키로 복귀하는 것을 보장할 수 없습니다.
이번은 **연결 유지형 대기**이며 `CONFIG_ZMK_SLEEP=n`입니다. 완전 전원 차단/초저전력 수면 구현을 완료한 버전이 아닙니다.

**실제 ARM 컴파일·링크, 실물 OLED/키보드, 충전 회로, 소비 전류는 검증하지 못했습니다.**
