# MODU-C + USB Dongle — 전체 ZMK 설정 저장소

**키맵 조각이 아니라, 좌우 키보드와 동글을 함께 빌드하는 전체 사용자 설정 저장소입니다.**

사용자가 제공한 개발자 기본 레포를 바탕으로, 사용자의 커스텀 배열과 3초 부트키를 적용했습니다.
제조사 공식 배포본이 아닌 비공식 수정본입니다. 기존 동작 펌웨어를 먼저 백업하십시오.

## 이번 수정: 동글 배터리 이벤트 링크 오류

`raise_zmk_peripheral_battery_state_changed` 미정의 오류를 일으키는 설정 조합을 수정했습니다.
화면 없는 동글과 OLED 동글 모두 `CONFIG_ZMK_BATTERY_REPORTING=y`로 변경했고,
`CONFIG_ZMK_SPLIT_BLE_CENTRAL_BATTERY_LEVEL_FETCHING=y`는 유지했습니다.
**키맵, 3초 부트키, 좌우 역할, 트랙볼 overlay, 빌드 대상은 이전 전체 ZIP과 동일합니다.**

이전 전체 저장소를 이미 올린 상태라면 같은 경로에 덮어쓰고 새 커밋으로 빌드하십시오.
소스 ZIP 자체를 GitHub에 파일 하나로 올리는 것이 아니라 압축 내부의 파일을 올립니다.
자세한 원인, 수정 경로와 검증 범위는 [오류 수정 안내](docs/BUGFIX_BATTERY_KO.md)를 보십시오.

## 들어 있는 구성

| 대상 | 설정 |
|---|---|
| MODU-C 왼쪽 | `ms88sf3/nrf52840`, split peripheral |
| MODU-C 오른쪽 | `ms88sf3/nrf52840`, split peripheral |
| 기존 Corne 동글 하드웨어 | `nice_nano/nrf52840/zmk`, split central |
| 트랙볼 | 오른쪽 입력 ID 0, 왼쪽 입력 ID 1을 동글에서 수신 |
| 키맵 | 기존 커스텀 7개 레이어 + 좌/우 부트 준비 레이어 2개 |
| 부트키 | 기본 레이어에서 5를 3초 누른 채 1 / 6을 3초 누른 채 0 |
| 빌드 | GitHub Actions, 6개 출력과 보드별 리셋 파일 |
| 동글 화면 | 기본 ZMK 상태 화면을 사용하는 OLED 버전과 화면 없는 버전 |

동글의 `nice_nano_v2` 표기는 이 레포에 고정된 ZMK의 보드 체계에 맞게
`nice_nano/nrf52840/zmk`로 바꾸었습니다. MODU-C용 파일과 동글용 파일을 서로 바꾸어 넣지 마십시오.

## GitHub에 올리기

압축 해제 후 **이 README와 나란히 있는 `.github`, `config`, `local-modules`, `scripts`,
`build.yaml` 등의 내용을 저장소 최상위에 그대로 넣습니다.** 바깥의 `modu-c-dongle-full` 폴더를
한 번 더 감싸서 올리지 마십시오. `.github`는 숨김 폴더일 수 있습니다.

이전 Obrey 설정에 일부 파일만 섞기보다는, 새 저장소나 새 브랜치에 이 트리를 기준으로 넣는 것이
명확합니다. 기존 저장소를 사용할 때도 예전 `local-modules/obrey-combo-boot`나 별도 Corne 빌드
워크플로우가 남아 있지 않도록 확인하십시오. 기존 동작 버전은 삭제하지 말고 별도 백업으로 보관하십시오.

`Actions → Build MODU-C + Dongle → Run workflow`를 실행합니다.
모든 작업이 성공하면 Artifacts의 **`modu-c-dongle-firmware`**를 받습니다.
그 결과 ZIP 안에 실제 설치용 `.uf2` 파일 6개가 생성되도록 구성되어 있습니다.
**현재 배포하는 소스 ZIP 안에는 컴파일한 `.uf2`가 없습니다.**

최초 설치는 [설치 안내](docs/FLASHING_KO.md)를 먼저 읽으십시오.
초기화 펌웨어를 올리기 전에, 연결이 없어도 다시 부트로더에 들어갈 수 있는 기존 복구 방법이 필요합니다.

## 부트로더 조작

기본 `Base` 레이어에서 모든 키를 놓고 0.3초 이상 멈춥니다.
왼쪽은 **5 하나만 3초 이상 누른 뒤, 5를 누른 상태로 1을 누릅니다.**
오른쪽은 **6 하나만 3초 이상 누른 뒤, 6을 누른 상태로 0을 누릅니다.**
두 키를 처음부터 같이 누르고 기다리는 조작이 아닙니다.

3초가 되기 전에 다른 키를 누르면 숫자 입력 쪽으로 확정되도록 설정했습니다.
3초 후에도 확인 키를 누르지 않고 5/6을 놓으면 부트 준비가 해제됩니다.
일반 숫자 입력은 유지되지만, 일반 `&kp`와 달리 키를 놓거나 판정이 확정된 시점에 숫자가 출력됩니다.
처음부터 길게 누르는 숫자 자동 반복은 부트 준비로 바뀝니다.
게임 레이어의 5/6은 일반 숫자키로 유지했고, 이 부트 조작은 Base에서 사용합니다.

부트 명령은 마지막에 누른 실제 1/0 키의 `&bootloader`로 실행하도록 구성했습니다.
반대쪽 키보드가 없어도 자기 쪽과 동글의 연결이 살아 있으면 조작할 수 있는 설계입니다.
연결 자체가 깨졌을 때 쓸 수 있는 하드웨어 복구 콤보는 아닙니다.
이 내용은 소스 기반 설계이며 실물에서의 성공을 보증하는 설명이 아닙니다.

## 화면과 부가기능 범위

`modu_dongle_oled.uf2`는 제공된 Corne 파일의 SH1106, I2C 주소 0x3c, SDA P0.17,
SCL P0.20 배선 정보를 사용하고, 기본 ZMK 상태 화면을 켭니다.
가로 해상도는 기본 UI에 맞춰 128로 설정했습니다(원본 커스텀 화면 설정은 129).
기존 DYA/Prospector/커스텀 동글 화면과 똑같은 UI를 재현한 것은 아닙니다.
화면 없는 `modu_dongle.uf2`도 함께 빌드합니다. 동글에는 둘 중 하나만 올립니다.

외부 포크의 런타임 센서 설정, 배터리 히스토리, settings RPC와 기존 커스텀 화면 모듈은 넣지 않았습니다.
ZMK Studio는 이번 기본 구성에서 켜지 않았습니다. 키맵은 파일 수정 후 빌드하는 방식입니다.
제조사의 MODU 보드·엄지키 방향 전환·트랙볼 드라이버는 그대로 참조합니다.

## 원본 소스를 받는 방식

ZMK와 제조사 하드웨어 코드 전체를 이 ZIP에 중복해서 넣는 방식은 아닙니다.
**개발자 기본 레포처럼 `config/west.yml`에 지정한 버전을 Actions가 자동으로 받아 빌드합니다.**
인터넷 연결과 해당 공개 저장소 접근이 필요하며, 오프라인 SDK 묶음은 아닙니다.

- ZMK: `641514a97db345f499dd50b0360e594270f008fe`
- MODU-C: `bee0bb4b812f63f279eb67e928accc89600b5904`

ZMK가 다시 가져오는 Zephyr 브랜치와 빌드 컨테이너까지 모두 불변 해시로 고정한 것은 아닙니다.
제조사 원본 핀 배치 및 방향 보정 파일은 덮어쓰지 않고, 좌우 역할·입력 전송 부분만 추가 overlay로 바꿉니다.

## 확인된 범위

현재 환경에서 소스 정적 검사, 14개 전체 구성 회귀 검사, 기존 HEX/UF2 패키징 자체 검사를 실행했습니다.
이번 수정은 동글 두 버전의 배터리 이벤트 링크 오류를 대상으로 합니다. 새 검사로 기존의 잘못된 설정
두 개를 모두 검출한 뒤 수정본에서 통과하는 것을 확인했습니다. 이는 ARM 링크 재현 검사가 아닙니다.
**ARM/Zephyr 전체 빌드, GitHub Actions 실행, 실물 연결/부트로더/OLED 동작은 검증하지 못했습니다.**
여기에는 ZMK 툴체인이 없고 외부 의존성을 내려받는 컨테이너 네트워크도 사용할 수 없었습니다.
테스트용 가짜 UF2는 임시 디렉터리에서만 사용했으며 배포 파일에는 포함하지 않았습니다.
실제 컴파일 결과는 Actions에서 확인해야 합니다.

```sh
python3 scripts/validate.py
python3 scripts/selftest.py
python3 scripts/test_full_config.py
```

세부 변경은 [변경 내역](docs/CHANGES_KO.md), 검증 범위는 [VALIDATION.md](VALIDATION.md)를 참고하십시오.
