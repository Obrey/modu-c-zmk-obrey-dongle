# MODU-C + Corne OLED dongle — MAC v3

**전체 GitHub 저장소 소스입니다. 이 ZIP 안에는 아직 실물에서 검증한 UF2가 없습니다.**
사용자가 화면 없는 버전에서 입력되는 것을 확인한 이전 구성의 무선 역할·보드·트랙볼 경로는 유지합니다.
이번 변경은 커스텀 키맵 적용 확인, OLED 상태 화면, 키보드 연결 LED입니다.

## 올리고 설치하기

이 폴더 **안의 내용 전체**를 기존 GitHub 저장소 최상위에 덮어씁니다.
`.github`, `build.yaml`, `config`, `local-modules`, `scripts`, `tests`가 최상위에 있어야 합니다.
이전 별도 빌드 워크플로우를 추가로 실행하거나 다른 실행의 결과물을 섞지 마세요.

`Build MODU-C + Dongle`의 **새 커밋 실행이 성공한 뒤**, 결과물
`modu-c-dongle-firmware`를 받습니다. 평소 설치용 파일은 최상위의 세 개입니다.

| 넣을 장치 | 이번 OLED 구성에 넣을 파일 |
|---|---|
| 모두 C 왼쪽 | `modu_left.uf2` |
| 모두 C 오른쪽 | `modu_right.uf2` |
| 코르네 동글 | `modu_dongle_oled.uf2` |

**이미 화면 없는 버전으로 입력된다면 이번 업데이트를 위해 settings_reset을 넣지 마세요.**
LED 동작은 키보드 펌웨어이므로 동글만 바꿔서는 변경되지 않습니다. 각 장치에 같은 빌드의 파일을 넣습니다.
화면에 다시 문제가 있으면 동글에만 `fallback/modu_dongle.uf2`로 돌아갈 수 있습니다.
`reset/` 안의 파일은 복구 전용이며 평소 설치 대상이 아닙니다.

## 새 화면

작은 Mac 모양 아이콘과 `MAC v3`를 고정 표시합니다. 운영체제 자동 감지가 아닙니다.

```text
[Mac] MAC v3        USB ON
L:  83%  ON
R:  77%  ON
D: USB POWER
0 Base             169054
```

위 83%, 77%는 설명용 예시입니다. 펌웨어는 수신한 실제 값만 표시합니다.
`169054`는 배포 시 커스텀 키맵 파일 SHA256의 앞 여섯 자리이며, 사용자가 키맵을 수정하면 달라집니다.

`L`, `R`는 각 키보드의 실제 BLE 연결 여부와 배터리 값입니다. `--%`는 아직 측정값을 받지 못했다는 뜻입니다.
배터리가 0%여도 연결되어 있다면 `ON`으로 표시합니다. 배터리 잔량과 연결 여부를 혼동하지 않습니다.
`USB ON` / `BTn ON` / `NO HOST`는 별도의 **동글→컴퓨터 연결**입니다.

처음 `L: press a key` / `R: press a key`가 뜨면 **왼쪽 `1`, 오른쪽 `0`을 각각 짧게 한 번** 누릅니다.
어느 장치가 어느 손인지 BLE 주소와 실제 키 위치로 식별해 저장합니다.
연결 순서만으로 0번을 왼쪽이라고 가정하지 않으므로, 기존 페어링을 지울 필요가 없습니다.
이 숫자는 일반 입력도 되므로 빈 메모장에서 누르세요. 저장 전에 전원을 끄거나 초기화하면 다시 요구할 수 있습니다.

동글에 실제 배터리가 있는지 확인되지 않았으므로 기본값은 **USB 전원 표시**입니다.
실제 배터리와 올바른 측정 회로가 있는 하드웨어에 한해 OLED conf의
`CONFIG_MODU_DONGLE_HAS_BATTERY=y`로 D행 잔량 표시를 사용할 수 있습니다.
전원에 연결된 MCU의 ADC값을 무조건 배터리 잔량이라고 표시하지 않습니다.

OLED의 SH1106, 주소 0x3c, SDA P0.17, SCL P0.20 배선은 첨부한 원본을 유지합니다.
흑백 색상·버퍼 설정을 보완하고, 화면 갱신을 별도 디스플레이 작업 큐에서 실행합니다.
실제 OLED 먹통 원인이 이것 하나였다고 확정된 것은 아닙니다. 화면은 유휴 상태에서 꺼질 수 있습니다.

## 키맵

수정하는 파일은 **`config/modu.keymap` 하나**입니다.
`config/modu_dongle.keymap`, `config/modu_dongle_oled.keymap`은 이를 불러오는 호환용 껍데기입니다.

이번 키맵 기준은 제조사 기본 배열이 아니라, 첨부된 **`modu-c-zmk-obrey-main.zip`의 커스텀 배열**입니다.
원래 7개 레이어의 모든 바인딩을 대조했으며, Base의 `5`, `6`만 3초 부트 준비 동작으로 바뀌었습니다.
원본 7개 레이어는 Base, Nav, Mouse, Game, FnMedia, Numpad, SymbolPad입니다.
좌우 Boot 레이어를 2개 추가해 총 9개입니다. 세부 대조는 `docs/KEYMAP_PROVENANCE.json`에 있습니다.

**앞서 받은 고정본도 소스상으로는 이 커스텀 배열이었습니다.** 실제 장치에서 다르게 입력된 원인이
잘못된/이전 UF2인지, 레이어 상태인지, 다른 이유인지는 확인되지 않았습니다.
이 버전은 키맵을 빌드 입력으로 명시하고, 생성된 Devicetree의 부트 키/67자리 구조를 검사하며,
화면에 버전·레이어·키맵 지문을 표시해 구분할 수 있게 했습니다.
이전 Studio 저장 키맵이 소스를 덮지 않도록 해당 저장 기능도 명시적으로 끕니다.
일반 배열을 바꾸는 후속 편집은 배포 시 지문과 다르다는 이유만으로 차단하지 않습니다.

커스텀 배열 안에도 **일반적인 배열의 Game 레이어**가 있습니다.
화면이 `3 Game`이면 왼쪽 맨 위 키(논리 위치 0)를 한 번 눌러 `0 Base`로 돌아갑니다.
Base에서 같은 키는 Game으로 이동합니다. 이 전환은 원래 커스텀 배열 그대로입니다.

### 부트로더

모든 키를 놓고 잠깐 멈춘 후, **Base 레이어**에서:

- 왼쪽: `5`만 3초 이상 누른 상태에서 `1`을 누릅니다.
- 오른쪽: `6`만 3초 이상 누른 상태에서 `0`을 누릅니다.

숫자 두 개를 처음부터 동시에 누르는 방식이 아닙니다. 반대편 키보드를 조작할 필요는 없지만
해당 키보드와 동글의 연결은 있어야 합니다. 연결 불량 상태의 하드웨어 복구 조작을 대신하지 않습니다.

## 키보드 상태 LED

| 상태 | 새 상태 LED 동작 |
|---|---|
| 해당 키보드가 동글에 연결됨 | 낮은 밝기의 초록색 지속 점등 |
| 저장된 동글을 찾는 중 | 파란색 느린 점멸 |
| 페어링 전 | 파란색 빠른 점멸 |

기존 드라이버가 `왼쪽 shield`라는 이유만으로 호스트 Bluetooth 프로필을 확인하던 분기를 제거합니다.
양쪽 모두 실제 split peripheral 연결 상태를 읽습니다. 물리적인 별도 충전 LED는 이 설정의 대상이 아닙니다.
기본 밝기는 12%입니다. 색상·극성은 제조사 소스를 따랐지만 실제 LED 색/밝기는 아직 실물 검증 전입니다.
